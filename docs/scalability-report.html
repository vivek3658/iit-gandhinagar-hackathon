2. Architectural Scalability Dimensions Scale Engineering

⚡ Fastify v5 Throughput Optimization

Fastify delivers unmatched throughput (over 40,000 req/sec per cluster instance) compared to Express or NestJS:

  • TypeBox Schema Pre-compilation: Route schemas are compiled ahead-of-time into high-speed C++ regex/V8 validators via fast-json-stringify, reducing JSON serialization overhead by ~80%.
  • Strict Asynchronous Return Handlers: Zero callback cascades or mixed reply.send() promises, ensuring predictable microtask event-loop scheduling.
  • Cluster Execution: Runs multi-process Node.js clusters via PM2 or Kubernetes Pods pinned to available CPU cores with sticky sessions.

🧠 Redis Memory Sizing for 10M Citizens

Calculated memory footprint for 10 Million registered accounts across Gujarat:

  • District Leaderboards (ZSET): 10M users × 128 bytes per entry = ~1.28 GB RAM for instant state-wide ranking across 33 Gujarat districts.
  • Active Mascot Mood Cache (HASH): 500k concurrent active daily users × 256 bytes = ~128 MB RAM.
  • Grid Nudge Broadcast Pub/Sub: Ephemeral channel overhead < 20 MB RAM.
  • Total Redis Cluster Sizing: 8 GB RAM instance provides 4x headroom with failover replication.

🗄️ Database Partitioning & Write-Behind Architecture

Preventing PostgreSQL row lock degradation under state-wide peak grid events:

  • Monthly Partitioning: Tables carbon_logs and task_completions are partitioned by month (e.g., task_completions_2026_11) to keep index trees compact in RAM.
  • Connection Pool Tuning: Pgbouncer connection pooler in transaction mode, capped at 100 dedicated pool connections to prevent backend process thrashing.
  • Read Replicas: Administrative analytics for GEDA command dashboards query dedicated read-only replicas without impacting citizen endpoints.

📢 Push Notification Fan-Out Pipeline

Broadcasting peak demand alerts to hundreds of thousands of homes within 60 seconds:

  • BullMQ Sharded Worker Pool: Citizen tokens are segmented by DISCOM circle (UGVCL, DGVCL, PGVCL, MGVCL) into 500-token batches.
  • Parallel Worker Scaling: 10 background worker processes process 50 batches concurrently, executing 25,000 FCM multicast dispatches per minute without rate-limit throttling.
